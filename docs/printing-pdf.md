# Native PDF output

The existing host exports `rv_host_print_pdf` and `rv_print_pdf_result`; generated `Ranvier.WebCore` interop declares the same functions and a 72-byte `PrintOptions`. `rv_abi_has("printing-pdf")` reports whether the loaded renderer includes PDF writing. Supported Skia package builds enable it by default; the current CoreGraphics backend reports unavailable.

For a reproducible supported source build, use `scripts/build.py` with an owned work/build directory and a unique private package version. `--enable-pdf` is the default; `--disable-pdf` provides a size-focused custom build. Every configure invocation explicitly sets `RANVIER_ENABLE_PDF=ON` or OFF so reusing a cache cannot silently retain the previous selection. No new RID, flavor or public package/version is allocated. The existing Skia/JPEG/font dependencies and notices apply.

The app settles required images and fonts before admission, supplies paper geometry/margins in points, and sets page/output limits. Rendering is synchronous on the host owner thread. The cancellation poll only reads cancellation state, before layout and between pages; it must not pump events or call the host. Printing restores screen layout/scroll before returning. The existing resource completion is delivered later; copy the bytes with `rv_print_pdf_result` and release every admitted operation with `rv_resource_release`. A completed byte result survives host destruction.

The raw ABI fixture is `tests/abi/printing_pdf.py`; it uses only the standard library unless `--inspect-pdf` explicitly selects the already-installed analysis tool. Default Skia CI requires actual supported output, while the current macOS/CoreGraphics profile requires controlled unsupported behavior. An enabled-provider qualification also runs the actual `tests/printing/Managed.fsproj` consumer in JIT and strict NativeAOT. A custom disabled build runs the raw fixture with `--expect-unsupported`. Independent PDF inspection checks page boxes, text, embedded fonts, images/vector rulers and physical dimensions. No PDF parser becomes a renderer dependency.

Distribution uses the existing supported native package identities, with allocated versions and fresh package-only consumer tests at integration. Two differently configured artifacts must never be published under the same package ID/version/RID. No plugin, new flavor or new package is introduced. Existing published packages predate this API; source/package qualification and public allocation remain pending the combined native cohort.

This boundary invokes no OS dialog or spooler. An app-selected OS provider handles printer selection, printable geometry and spool-job lifetime after renderer output is available. macOS/CoreGraphics, vertical writing, page pseudo-classes, tagged/accessibility PDF and link destinations remain unqualified.
