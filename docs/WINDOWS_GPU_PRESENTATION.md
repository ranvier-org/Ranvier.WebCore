# Windows shared GPU presentation

The feasibility executable in `tests/gpu/SharedTextureSpike.cpp` uses the installed GPU runtime and SDL3. It renders with ANGLE into an `ID3D11Texture2D`, opens that resource on SDL's separate D3D11 device, wraps it in an SDL texture, flushes SDL's draw batch and presents. It verifies both the shared resource and SDL's actual swapchain backbuffer. The verification copies are test instrumentation; presentation does not copy through a CPU pixel buffer.

## Source contracts

- SDL exposes its D3D11 device through `SDL_GetRendererProperties` and `SDL_PROP_RENDERER_D3D11_DEVICE_POINTER`: <https://wiki.libsdl.org/SDL3/SDL_GetRendererProperties>.
- SDL accepts the consumer device's `ID3D11Texture2D` through `SDL_CreateTextureWithProperties`: <https://wiki.libsdl.org/SDL3/SDL_CreateTextureWithProperties>. Its D3D11 implementation obtains its own COM reference with `QueryInterface`, then releases it when destroying the SDL texture: <https://github.com/libsdl-org/SDL/blob/main/src/render/direct3d11/SDL_render_d3d11.c>.
- ANGLE requires imported D3D textures to belong to its queried D3D device. The cached WebKit ANGLE version accepts `EGL_D3D11_TEXTURE_ANGLE` for EGLImage creation (`validationEGL.cpp`), while the newer extension specification also describes `EGL_D3D_TEXTURE_ANGLE`: <https://github.com/google/angle/blob/main/extensions/EGL_ANGLE_d3d_texture_client_buffer.txt>.
- D3D11 supports an NT shared handle and keyed mutex together. Each device must acquire the mutex before issuing commands that access the resource: <https://learn.microsoft.com/en-us/windows/win32/api/d3d11/ne-d3d11-d3d11_resource_misc_flag>.

## Intended production ownership

The native host queries its current EGL display's D3D11 device and allocates the producer texture there. It creates an NT shared handle, opens the texture on the supplied SDL renderer device, and closes the handle immediately. The native transport retains both device references and both views of the texture. A separate opaque acquired frame retains the surface so resize and host destruction cannot invalidate an outstanding texture lease.

Producer rendering acquires key 0, renders the existing TextureMapper layer tree into an EGLImage-backed framebuffer, flushes ANGLE, and releases key 1. Acquire returns only after the consumer has acquired key 1. The caller uses the returned borrowed texture pointer with SDL, flushes the SDL command batch or presents, and releases the frame. Frame release flushes the consumer device context and releases key 0. Each mutex wait is bounded to 16 ms. A surface cannot be acquired twice concurrently. All operations use the host/SDL owner thread. Call `rv_host_update` before acquiring, just as before CPU paint, so WebCore advances animations and commits compositing geometry.

The GPU texture contains premultiplied RGBA8. It must be presented with the corresponding SDL blend mode (or no blending for an opaque final image). The existing CPU API continues returning straight-alpha RGBA. Unsupported devices, missing ANGLE extensions and unsupported scale return a recoverable result and retain the CPU path. The existing compositor only supports device scale 1; extending that requires actual page-content and geometry tests.

## Milestones and acceptance

1. **Feasibility:** compile the standalone spike, then run under a separate application lease. Verify shared texture content, SDL swapchain orientation/content, 18 handoffs, three surface sizes, closed OS handles and successful process teardown. Completed on NVIDIA D3D11 with the cached GPU stage.
2. **Native transport:** implemented isolated D3D/EGL surface creation, bounded synchronization and resource cleanup. Repeated failed cross-adapter acquisitions exposed deferred D3D destruction; releasing resource interfaces before flushing the producer device stopped the observed one-handle-per-failure growth. See Microsoft's [Flush lifetime guidance](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-id3d11devicecontext-flush).
3. **Host integration:** implemented framebuffer selection without readback, an opaque frame lease and ordinary metadata out parameters. Actual WebCore DOM content passed SDL swapchain assertions, resize with a retained old frame, 36 asynchronous surface reuses per teardown mode, busy/thread checks, 25 incompatible WARP acquisitions, bounded process-handle growth and explicit/host/renderer/window teardown. Scale 2 returns unsupported and CPU paint now flattens composited layers, fixing the previously omitted child content. The standalone spike also verifies premultiplied half-alpha green over blue in SDL's backbuffer.
4. **Presenter integration:** Views owns SDL texture creation/destruction and calls SDL presentation before native frame release. Recreate the wrapper when the resource or renderer device changes. Root owns the Views integration and package/ABI coordination.

Local spike commands are `python tests/gpu/spike.py` for compilation and `python tests/gpu/spike.py --run-only` for execution; pass `--native`, `--build` and `--sdl` to override the local cache defaults. The helper mutates only this worktree's ignored `artifacts/gpu-spike` directory. It discovers the installed Visual Studio toolchain with vswhere. The spike is not a production host acceptance test.

For the actual host acceptance, run `python tests/gpu/run.py --native <GPU-runtime-directory> --sdl <SDL3.dll> --build-only`, then the same arguments with `--run-only --teardown all`. It links no private WebCore APIs or import library: the executable loads the packaged C exports and verifies the SDL swapchain. The helper uses ambient `cl` or discovers Visual Studio, with `--compiler-environment` as an explicit override. A local `--runtime-overlay` can stage privately rebuilt DLLs without modifying the supplied runtime. The current evidence uses such a private host/WebCore relink against the existing GPU cache, not a newly packaged release or CI artifact.

Integration requires copying both `RanvierWebCoreD3D11.cpp` and `.h` into the prepared host source directory. The CMake host target includes the source and links ANGLE EGL, D3D11 and DXGI for Windows GPU builds. Coordinate the ABI version and canonical `Native.fs` declarations for `RvGpuFrame`, `rv_host_acquire_d3d11_frame`, `rv_gpu_frame_info` and `rv_gpu_frame_release` separately; this branch deliberately leaves the ABI version unchanged.
